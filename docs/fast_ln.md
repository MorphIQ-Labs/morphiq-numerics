# Bounded natural logarithm

`fast::elementary::ln(x)` approximates the natural logarithm of the exact
binary64 input. `ln_slice(x, out)` returns the same bits elementwise, using
the existing NEON/SSE2/AVX2/AVX-512 dispatch when SIMD is enabled. A length
mismatch panics before writing outputs. Existing elementary APIs are unchanged.

## Numerical decision and consumer purpose

For finite `x > 0`, writing `L = ln(x)` and `Y` for the returned value,

```
abs(Y - L) <= 2^-53 * abs(L) + 2^-65.
```

This is an absolute error in natural-log units, including final rounding.
It budgets the quantity propagated by `exp(log leg + log probability + …)`.
Argument formation, addition of logarithms, derivatives, inverse problems
and the final exponential require separate consumer qualification. The bound
is a mathematical allowance, not an observed error fitted to existing samples.
Correct rounding and faithful rounding are not promised.

| Region | Output/error semantics | Cost target and justification |
| --- | --- | --- |
| Finite positive input | Mixed absolute bound above | One fixed reciprocal stage; compare scalar throughput and dependent latency with pinned CORE-MATH log and SLEEF u10 log |
| `1/2 <= x <= 2` | Absolute bound at most `2^-53 * ln(2) + 2^-65`; exact `ln(1)=+0` | Near-one cancellation remains in the reduced residual; no fixed absolute rounding tolerance is used in the oracle |
| Other finite positive inputs, including subnormals | Equivalently relative `2^-53 + 2^-65/abs(L)` | Exact normalization and the same fixed stage; no arbitrary-precision fallback |
| Zeros, negatives, infinities, NaNs | Existing strong-owner bits, including NaN payloads and `ln(±0)=-∞` | Packets containing special values delegate to the bounded scalar entry |

For a consumer using the returned value, exact real arithmetic gives
`abs(Y-L) <= (2^-53*abs(Y) + 2^-65)/(1-2^-53)`.
The additive term is an offline, whole-domain bound on the existing stage,
not a runtime threshold or a near-one branch. It is about `2.71e-20` log units.

## Derivation and bounded work

The reduction and polynomial are those in [ln.md](ln.md), generated by
`generators/ln_constants.py` and `generators/ln1p_constants.py` from the
published mathematics cited there. No external implementation source is used.
The implementation reuses `Reduced::of` and `stage::normalized_parts`, and returns
`RN(s + lo)`. In lanes it reuses the identical reduction and reciprocal stage
in `ln::lanes::fast_ln`. Unused error-estimate and rounding-test values are
dead results; generated-code inspection must establish their removal in
each measured calling context.

There are no refinement iterations or unsupported positive finite inputs.
The 512-cell reciprocal table, split log table and degree-six correction
retain their existing generated bits and certificates. The strong entry
retains its Ziv decision and accurate fallback; this entry has neither.
The slice screens positive finite packets before arithmetic. A packet containing
a special value finishes through the bounded scalar entry, which delegates
only special values to the strong owner. Regular packets use one flat loop over
full vectors. Fixed power-of-two packets and one/two-element scalar remainders
use the established bounded-exp dispatch structure to avoid bulk-loop setup on
short calls. Otherwise the last partial packet is padded with 2 and only its valid prefix
is stored. It stays in the selected SIMD width instead of entering a second
backend for the remainder. One is accepted in these packets: the reciprocal
and table terms are exactly one and zero, so the result is exact positive
zero (`FastLn.fast_ln_regular_one`). This keeps the scalar arithmetic and
outputs unchanged, including mixed packets and all slice lengths.

Scalar and SIMD ln omit the second reduction exponent once normalization
has established its interval. The scalar positive-finite screen uses the
equivalent unsigned encoding interval; it preserves every special value.
The SIMD normalizer skips scaling for a packet of normal inputs and constructs
the scalar normalizer's same significand and exponent directly from the input
bits. Since that significand is already in the reciprocal stage's fundamental
interval, the second reduction exponent is zero. These exact specializations
and the lossless packed table layout are shared with strong `ln` lanes and
proved in `LnNormalized.v`; [lanes.md](lanes.md#5-ln-and-ln_1p) gives the bit
identities. They change neither polynomial evaluation nor any returned bit.
The SIMD layout adds 8 KiB of read-only data; memory-pressure and strong-path
control measurements are part of its cost qualification.

`LnStageEvaluation.ln_eval_bounded` proves finite `s`, `lo` and `eps`, with
`0 <= eps <= 2^-65`, and, for the exact logarithm,

```
abs(L - (s + lo)) + u*(abs(lo) + eps) <= eps,  u = 2^-53.
```

These are real sums. The normalizer's existing proof applies to every
positive finite binary64 input, subnormals included. Let
`d = abs(L - (s+lo))`. Rounding the sum of two binary64 values has relative
error at most `u` (a subnormal exact sum is representable). Thus

```
abs(RN(s+lo) - L) <= u*abs(L) + (1+u)*d
                  <= u*abs(L) + eps.
```

The second inequality uses `d <= eps` and the certificate's rounding margin.
`formal/fast/FastLn.v` composes the normalizer, complete IEEE stage evaluation,
final rounding and public screens. The bound does not assume a successful
Ziv decision, a worst-case distance from a rounding boundary, or sampled
accuracy. `x=1` returns exact positive zero separately.

Independent high/low observations are generated at 600 and 1000 bits by
`generators/fast_ln_reference.py`, with explicit reference uncertainty. Inputs
include the strong fixture's published worst cases, reciprocal cell edges,
all normal exponents, subnormal extremes and neighbors of one. The oracle
test performs the budget comparison using exact integer arithmetic.

## Cost acceptance and paired evidence

The purpose and repeated-use attribution are recorded in
[#193](https://github.com/MorphIQ-Labs/morphiq-numerics/issues/193).
Reuse the native [benchmark methodology](../scripts/bench_fast/README.md)
and campaign controller. CORE-MATH at
`c7100a07428584639defdd64409e3621884c362b` supplies a correctly rounded
scalar comparator; SLEEF 3.9.0 at
`906ca7512ee483296780a81a21b9ca715d40dfe1` supplies u10 scalar and native
SIMD logarithms. They do not establish this library's NaN-payload or
cross-target identity guarantees. The mixed bound and a one-ULP bound
are not interchangeable near one; report both contracts explicitly.

Qualification requires separately declared scalar throughput, dependent
latency, short/remainder and large-slice cells on native ARM and x86,
including ordinary, near-one, wide-exponent, subnormal and mixed inputs.
Use the existing ten-process paired protocol, frozen counts, retained failed
attempts and one-sided 95% upper ratio at most one for each required cell.
No aggregate may hide a failed cell. Include strong-path controls, dispatch
and wrapper costs, allocations and code/table footprints. CI supplies
correctness evidence, not performance qualification.

Stop this candidate's qualification when a required cell fails. Inspect
the actual caller's code and profile before changing the kernel or dispatch;
a new candidate or protocol requires a new declared attempt. Retain exact
source/settings/input identities and all timing samples under ignored
`target/` through review. Selection, native results, remaining evidence and
owner disposition belong to the issue/PR, not to this derivation.
