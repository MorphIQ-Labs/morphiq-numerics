# Explicit fast primitives

These explicit approximation APIs have separate IEEE/Coq entry proofs and
Gappa arithmetic certificates for the bounds below. Source bindings connect
the proofs to the implementation. Sampled agreement and native performance
measurements are separate evidence; neither substitutes for a whole-domain bound.

The `fast` namespace selects a bounded approximation explicitly. Existing
`elementary` and `normal` functions keep their contracts and dispatch. No
feature changes an existing API's numerical identity.

| API | Accelerated domain | Error bound there |
| --- | --- | --- |
| `fast::elementary::exp` | `abs(x) < 704` | Relative `2^-51` |
| `fast::normal::erfcx` | `-0.5 <= x < 16`, `abs(x) >= 2^-33` | Relative `2^-51` |
| `fast::normal::norm_cdf` | `2^-33 <= abs(x) <= 8` | Absolute `2^-49` |

Each function has a matching `_slice(x, out)` API. Results in the accelerated
domains are finite and normal. The CDF has no relative-tail guarantee inside
its accelerated domain. Correct rounding and
faithful rounding are not the fast contract. Scalar and slice results must be
bit-identical within this namespace; fast and strong results may differ.

Outside the stated accelerated domain, each entry delegates to its corresponding
strong API and inherits that API's bound and special-value behavior. This keeps
gradual underflow, overflow, signed-zero conventions, NaN payloads and infinities
with their existing owners. An accelerated-domain limit is a dispatch boundary,
not an input refusal. No tail probability is deliberately flushed by these APIs.

## Shared arithmetic and bound derivation

The mathematical definitions and source references are those in [exp.md](exp.md),
[erfcx.md](erfcx.md) and [normal.md](normal.md). The bounded exponential's
1024-way constants are generated by `generators/fast_exp_constants.py` at
600-bit precision. Its cubic coefficient `d3` reuses `exp_poly.sollya`;
erfcx and CDF reuse `generators/erfcx/fast_tables.py` and
`generators/normal_constants.py`. Let `u = 2^-53` be binary64 unit roundoff.
The published fast allowances are `4u` relative for exp/erfcx and `16u`
absolute for CDF. The following composition estimates are tighter.

**Exponential.** The 1024-way reduction gives `R = x - n*ln(2)/1024`,
`abs(R) <= 0.000338451`, and `r = RN(R + dr)` with `abs(dr) <= 2^-77`.
`FastExpReduction` proves the index, exact leading subtraction and this
residual bound over `abs(x) < 704`. A reflective integer certificate in
`FastExpTables` checks all 1024 generated double-word entries against exp;
only their high words enter a shared static bounded runtime table (8 KiB).
Static storage prevents separate scalar/SIMD constant promotions from duplicating
the table in the linked image. Word `j` is
pre-biased by subtracting `j << 42`, modulo `2^64`. Adding the complete
reduction encoding shifted left by 42 cancels the index contribution and
supplies the exponent scale. `FastExpScale.fast_biased_lookup_ok` proves
this identity, including negative reductions. The strong implementation
retains its own reduction and tables.

The cubic correction is constrained to vanish at zero, preserving `exp(0)=1`.
Write `A = 0.000338451` and approximate the quartic term `r^4/24` by
`alpha*A^2*r^2/24`. On `t=r^2/A^2` in `[0,1]`, minimizing the maximum
of `abs(t^2-alpha*t)` equates the endpoint residual `1-alpha` and the
interior residual `alpha^2/4`. Thus `alpha=2*(sqrt(2)-1)` and the maximum
is `3-2*sqrt(2)`. The generator rounds
`c2 = 1/2 + alpha*A^2/24` once to binary64. The operation sequence is:

```
r2 = RN(r*r)
p = RN(c2 + RN(r*d3))
u = RN(r + RN(r2*p))
y = RN(H * RN(1 + u))
```

Here `H` is the table high word scaled by `2^k` through its exponent field.
`FastExpScale` establishes exact scaling for `-1016 <= k <= 1016`.
`fast_cubic.g` uses the existing degree-five analytic certificate and a
completed-square identity for the omitted terms. It includes coefficient,
reduction and arithmetic errors and proves
`abs(u - (exp(R)-1)) <= 7*2^-56`. This saves two multiplications and one
addition relative to the 512-way quartic, at the cost of 4 KiB more table
storage. It spends previously unused accuracy budget within the unchanged
public contract; the observed error is reported separately from this proof.

`FastExpReconstruction` first rounds `1 + u` and then multiplies by `H`.
Both operations have normal results throughout the accelerated domain.
Their normalized rounding-error bounds are `1025*2^-63` and `1026*2^-63`.
This order avoids a subnormal correction product near the negative end of
the domain. `FastExp.fast_exp_entry_ok` composes the polynomial, table and
reconstruction bounds to establish the existing relative `4u` guarantee.

The slice path evaluates the same operations using bounded scalar table loads
assembled into SIMD lanes. Hardware gather is deliberately avoided: its
latency can dominate on processors with the Gather Data Sampling microcode
mitigation ([Intel performance analysis](https://www.intel.com/content/www/us/en/developer/articles/technical/software-security-guidance/resources/gds-mitigation-performance-analysis.html)).
A full-vector domain check precedes arithmetic. A packet containing a screened
input finishes through the scalar fast/strong owners; this preserves the
scalar bits and keeps invalid intermediates out of inactive lanes. Cold slice
packets pass their slices by reference, avoiding a returned lane-array spill
on the hot path. Two independent vectors are scheduled per bulk iteration.
Power-of-two batches of up to eight vectors carry fixed-size references
across the dispatch boundary. Their combined domain mask is checked before
arithmetic; groups of four vectors expose independent table work. One- and
two-value remainders use scalar evaluation before the fixed batch, as do
AVX2/SSE2 tails. Larger AVX-512 remainders use checked partial loads/stores.
Static AVX builds keep fixed packet kernels outside the dispatcher too; their
register saves must not burden a short call selecting a different packet.
Runtime detection already introduces this ISA boundary, so its helper inlines.
The SSE2 fallback loop and scalar-remainder helper are kept outside the runtime
dispatcher so their register needs do not burden every selected backend. The architecture
API owns index masking and prefix-length validation. The lane code-generation
gate rejects hardware gather in these bounded kernels.

**Scaled erfc.** The bounded path retains the original table reduction,
177 cells, degree-nine polynomials and generated coefficient bits. It evaluates
only their high words, pairing adjacent coefficients:

```
h2 = RN(h*h)
p[i] = RN(a[2*i] + RN(h*a[2*i+1]))       # i = 0..4
Y = RN(p[0] + RN(h2*RN(p[1] + RN(h2*RN(p[2]
    + RN(h2*RN(p[3] + RN(h2*p[4]))))))))
```

This costs 19 binary64 additions/multiplications after reduction. Each generated
`fast_T*.g` certificate accounts for the omitted three low words and the exact
rounding sequence over the complete cell. It bounds relative evaluation error
against the original full polynomial by `7*2^-54 = 3.5u`, with positive output
in `[1/64,4]`. The existing analytic table error is at most `2^-69`; their
composition is less than `4u`. `FastErfcxEvaluation`, `FastErfcxCertificates`
and `FastErfcx` connect the certificates to the IEEE operations and public screen.
`generators/fast_certificates.py` replays the arithmetic certificates from the
existing generated constants. The strong compensated evaluator is unchanged.

The public erfcx slice runs the inlined scalar evaluator. CDF's vector
composition shares a lane version with exactly the same operation order.
Tiny arguments, negative reflection, reciprocal tails and extreme outputs
retain their original strong owners.

**Central CDF.** For `abs(x) <= 1` within the accelerated domain, the bounded
CDF uses the degree-25 integrated Gaussian Taylor polynomial with the high
words of the existing 13 `CENTER` coefficients and density constant. It pairs
adjacent coefficients in `z = RN(x*x)` and evaluates the six pairs in
`zz = RN(z*z)`, then returns `RN(0.5 + RN(RN(x*DENSITY_HIGH)*p))`.
There are 29 additions/multiplications, with no transcendental calls.

`fast_center.g` accounts for the stored coefficients, density error and all
roundings, giving an absolute arithmetic bound of `4u` against the exact
integrated polynomial. `FastNormalCentralAnalytic` integrates the pointwise
Taylor remainder instead of discarding its integration variable. For degree
12 in `x*x`, the remainder is bounded by

```
D * abs(x) * (x*x/2)^13 / (13! * 27) <= 3u,  abs(x) <= 1.
```

The combined central bound is `7u`, within the existing `16u` contract.
`FastNormalCentral` transcribes the binary64 sequence and composes its error
with the analytic remainder. Both neighbors of `abs(x)=1` belong to the
oracle, scalar/slice and extracted-entry checks.

**CDF with an absolute probability budget.** For `1 < a = abs(x) <= 8`, set
`y = a/sqrt(2)` and `q = a*a/2`. The defining Gaussian integral gives
`Phi(-a) = exp(-q) * erfcx(y) / 2`. Use the high word of the existing generated
`INV_SQRT2` constant (`generators/normal_constants.py`) and the same generated exp
and erfcx tables as above. The scalar sequence is:

```
z = RN(a * INV_SQRT2_HIGH)
t = RN((-0.5 * a) * a)
lower = RN((0.5 * fast_exp(t)) * table_erfcx(z))
result = lower if x < 0 else RN(1 - lower)
```

`table_erfcx` uses the paired high-word polynomial above. Its table bound applies
also when scaling puts `z` below the public fast erfcx tiny-input screen.
All intermediate values here are normal. Multiplication by `0.5` is exact.
Neither the accurately squared exponent nor a low-word argument correction is
needed for this contract.

For clarity, this composition uses conservative bounds with explicit slack.
Rounding the constant and its product gives `abs(z-y) <= 3u*y`; rounding the
square gives `abs(t+q) <= u*q`, with `0 <= q <= 32`. For positive arguments,
the defining integral
`F(y) = erfcx(y) = 2/sqrt(pi) * integral_0^infinity exp(-s*s-2*y*s) ds`
implies `0 < F(y) <= 1` and `abs(F'(y)) <= 2/sqrt(pi)`. Thus the scaled-argument
contribution is at most
`3u/sqrt(pi) * y*exp(-y*y) < u`.
The exponent-rounding contribution is at most
`0.5 * exp(-q) * (exp(u*q)-1) <= 0.5*u*q*exp(-(1-u)*q) < u`.
These estimates also cover their joint effect by evaluating the exponent
perturbation with `F(z) <= 1`, then the argument perturbation with `exp(-q)`.

The two table results have relative errors at most `4u` each, and the final
product adds at most `u`, so their combined relative error is bounded by
`(1+4u)^2*(1+u)-1 < 10u`. Before these perturbations the product is at most
`exp(32u)/2 < 0.51`, giving an absolute contribution below `6u`.
The positive complement rounds with absolute error below `u` (its magnitude
is below two). The total is therefore below `9u < 16u = 2^-49`.
This is an absolute bound; multiplying by a relative-tail budget would be
incorrect. Beyond `abs(x)=8`, the existing strong tail path supplies the result.

The CDF SIMD path follows the scalar branch selection and arithmetic sequence.
Central and outer lanes receive benign inputs before inactive arithmetic;
screened outputs come from the corresponding strong scalar entry. No feature
changes the selected contract or the scalar result bits.

The derivation above is distinct from a sampled error result. Independent
reference fixtures include their oracle uncertainty when checking the fast
bound. Exp fixtures retain a 192-bit interval reference, compared using exact
arithmetic, so binary64 reference rounding cannot exhaust a valid result’s
error budget. Rounded Gaussian references include their half-ULP uncertainty. Mixed inputs, dispatch endpoints, SIMD remainders and retained
special values are checked separately. The extracted entry models exercise the
same central/outer and accelerated/fallback decisions. Native measurements
apply only to their recorded hosts, calling interfaces and input populations.

## Consumer use

Choose an explicit primitive contract from the consumer's error budget.
Competitors need not match our numerical accuracy: each must satisfy the actual
use-case budget, and cost decides among acceptable choices. Extra accuracy
beyond that requirement earns no independent credit. Matching algorithm
parameters or comparing result bits is diagnostic evidence, not the acceptance
objective. Report error-versus-cost curves and ordinary/difficult populations
separately when the selected computation changes with the required budget. A CDF
absolute error does not by itself qualify cancellation-sensitive prices,
Greeks, inverse problems or tail-relative accuracy. Retain exact-input
independent references and measure the full consumer calculation as well as
individual kernels. Extra digits are not an independent optimization objective.

`bench-fast-primitives` compares public scalar and slice entry points on fixed
52-value packets in alternating order. Its optional input file produces scalar/
slice observations from exact input encodings for independent fixture analysis.
Neither a local speedup nor fixture agreement establishes universal competitor
parity, a whole-consumer contract, or native results on an unmeasured host.

The CDF composition enters exp's screened scalar/lane kernels directly.
`FastNormalArgument.fast_normal_exponent_ok` proves that its rounded exponent
is in `[-32, 0]` after the CDF's public magnitude check; inactive SIMD lanes
use magnitude one. This avoids a duplicate exp screen and an unreachable
strong-exp fallback. Debug assertions check the internal precondition, and
public exp retains its own screen. The sibling erfcx composition likewise
uses its table kernel under the already-proved argument range.
