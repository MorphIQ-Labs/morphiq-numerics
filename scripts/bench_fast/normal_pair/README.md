# Normal-pair native benchmarks

This harness compares the public bounded normal pair with two standalone
polynomial candidates and black-box system libm controls. All use the existing
uniform map and hardware correctly rounded square root. The public contract
and its proofs are in [fast_random.md](../../../docs/fast_random.md); existing
strong pairs retain their original results.

The consumer is MorphIQ Risk's local-volatility Monte Carlo. The public
interface is a word-to-pair function in `fast::random` with a scalar-identical
slice form. Both preserve the existing `random::normal_pair` uniform maps,
two-word consumption and octant fold. General fast trigonometry, new random
streams, rejection sampling and changes to existing APIs are outside this
investigation. Consumer pricing qualification remains separate.

## Numerical decision under investigation

| Region / output | Candidate error budget | Semantics | Cost comparison |
| --- | --- | --- | --- |
| Every pair of `u64` words, each normal output | Absolute difference at most `2^-38` from the existing strong pair; a proof is required before any public guarantee | Finite outputs, the same uniform grid and octants, scalar-identical slice results | Same-host libm Box–Muller; strong pair is a diagnostic control |

An absolute budget handles angular zeros. This candidate budget comes from
composing the existing logarithm's bound through the radius, rather than from
Monte Carlo sampling noise. Let `L = -ln(u)` for the existing open-uniform
grid. Then `2^-53 <= L < 37`, and the standalone polynomial candidates use the public fast logarithm's
bound `2^-53 L + 2^-65`. The public normal pair uses the private radius
logarithm described in [fast_random.md](../../../docs/fast_random.md): that
same bound near one, and `2^-48 L + 2^-45` away from the reciprocal-one
cells. The absolute term matters as `u` approaches one.
The radius perturbation follows from
`sqrt(a) - sqrt(b) = (a-b)/(sqrt(a)+sqrt(b))`; correctly rounded square roots,
the bounded angular polynomials and final products add their own errors.
The screen only tests this budget on the independent fixture. The public
whole-domain proof is separate; neither establishes consumer sufficiency.

Both candidates use Chebyshev interpolation generated by mpmath 1.4.1 at
200 bits for `sin(sqrt(z))/sqrt(z)` and `cos(sqrt(z))`, with the removable
singularity defined as one. The interval is
`0 <= z <= RN(pi/4)^2`. Six coefficients give degree-11 sine / degree-10
cosine, and seven give degree-13 sine / degree-12 cosine. Rounded binary64
coefficients are evaluated by separate multiply and add in Horner order.
All constants are generated into the ignored run directory.

No external implementation source is used. These are polynomial interpolation
of mathematical functions, using the crate's existing exact octant reduction.
The engine kernel identified in #282 is not consulted because of the
repository's provenance restriction on Cephes-derived source.

Relevant established designs include the
[Box–Muller transform](https://doi.org/10.1214/aoms/1177706645) and the bounded
polynomial / range-reduction approach described in the
[SLEEF paper](https://arxiv.org/abs/2001.09258). A general-purpose trigonometric
library carries reductions unnecessary for this fixed octant domain.
The existing crate's logarithm, square root and uniform mapping are reused;
the screen compares freshly generated short polynomials for the remaining work.

## Prepare and observe

Run on native x86-64 Linux with AVX2/FMA or native Apple Silicon macOS, using
the pinned Rust toolchain, C compiler and existing generator environment.
On Linux, preparation builds a
standalone Rust `cdylib` with `std,simd`, `target-cpu=x86-64-v3`, one codegen
unit and fat LTO. The C comparator uses `-O3 -march=x86-64-v3`, disabled
contraction, black-box system `log` and `sincos` calls, and hardware square root
with `-fno-math-errno`, matching the Rust candidate's square-root instruction.

On Apple Silicon, the wrapper uses `target-cpu=apple-m1`, the C timer uses
`-mcpu=apple-m1`, and both libraries are native `.dylib` files. The C control
calls Apple's public `__sincos` entry; Rust uses its platform `sin_cos`.
Observation must verify that the Rust and C controls return identical bits.
Apple system libm remains a black box: its load commands and macOS build
identify the OS dyld-shared-cache implementation; there is no claim of a
standalone libm-file hash. Compiler versions and all actual flags are retained.

```sh
target/generators-venv/bin/python scripts/bench_fast/normal_pair/screen.py \
  prepare target/issue-282/screen-01
python3 scripts/bench_fast/normal_pair/screen.py \
  observe target/issue-282/screen-01
```

The independent interval-oracle fixture covers 3,168 strong pairs, including
radial extremes, octant boundaries and seeded streams. Observation requires
the strong function to reproduce every fixture bit and the candidates to
satisfy the candidate absolute budget on every fixture row. Observed maxima
and worst witnesses are retained; sampled maxima are not proved bounds.

The two libm controls use either the identical octant fold or the textbook
full angle, both with the same word-to-uniform map. The engine's zero-rejection
map is a different stream contract and is not silently substituted. Neither
control establishes cross-target determinism or a correctly rounded guarantee.

## Timing and stopping condition

```sh
python3 scripts/bench_fast/normal_pair/screen.py \
  measure target/issue-282/screen-01 --cpu 2
```

On Linux choose an allowed CPU with an idle SMT sibling. On macOS omit
`--cpu`; supplying it is an error. Every timing process establishes
`QOS_CLASS_USER_INITIATED`, as in the existing ARM runner. This is not CPU
affinity and does not guarantee performance-core residency. Preparation and observation
finish before timing. The manifest records source revision and source hashes,
compiler versions, flags, CPU, libc version, exact input banks and binary
hashes. Each operation verifies the frozen inputs. Keep the run directory
and every pilot / sample through review; timing refuses to overwrite a run.

The predeclared screen uses three banks of 4,096 pairs: seeded ordinary words,
radial endpoints, and octant edges. All eight implementations have the same
pair-return ABI and function-pointer calls. Outputs are stored. Seven
repetitions alternate the complete function order, with warmups and a pilot
targeting 30 ms per sample. Report medians and the complete range; retain
all samples without outlier removal. This is independent pair throughput,
including the common wrapper cost, with uncontrolled host contention and
frequency. No parity decision follows from it.

Stop this screen after the declared run. It answers whether a focused angular
polynomial merits the larger proof and native performance qualification.
A candidate needs lower ordinary-bank median cost than both libm controls
and fixture errors within the candidate budget to justify that next stage.
Select a polynomial size using cost and error together; an extra coefficient
needs an accuracy requirement or measured cost benefit. Endpoint banks expose
cost/error regions independently of ordinary frequencies.

Issue acceptance still requires certified approximation/evaluation/composition
bounds, a source-bound proof, scalar/slice identity, cross-target determinism,
and controlled native scalar/slice and stream measurements on x86 and ARM.
Dependent latency and the consumer's cached/antithetic reuse need their own
measurements. The existing native benchmark procedure supplies the paired
multi-process uncertainty rule for that qualification. This screen does not
claim to satisfy those gates.

## Public API qualification

After the independent observation passes, use the shared paired protocol:

```sh
python3 scripts/bench_fast/normal_pair/qualify.py \
  target/issue-282/public-01 --out target/issue-282/qualification-01 --cpu 2
```

Prepare and observe `public-01` with the commands above, substituting that
fresh directory for `screen-01`. Freeze source before preparation. Finish
builds, tests, proofs, code inspection and profiling before uninstrumented
timing. The runner and shared protocol are copied into the prepared snapshot
and must match their frozen versions.

The 32 required cells compare the public product with each libm control:
scalar throughput on all three banks; dependent scalar latency on ordinary
and radial-edge banks; ordinary slices of lengths 1, 2, 7, 8, 9, 17 and
4,096; radial-edge and octant-edge slices of length 4,096; Xoshiro256++ plus
normal-pair generation; and a synthetic cached/antithetic composition using
both normals in two updates. The public slice writes Rust tuple storage,
with allocation outside timing. Each process reuses identical input/output
buffers for the product and reference and records their addresses. The reference loop writes the same tuple
storage, without an assumed C/Rust tuple layout. The reference slice helpers
inline their Rust Box–Muller statements and call the platform primitives as
black boxes; there is no per-pair function-pointer or adapter call. Observation
requires their scalar results to equal the C controls bit for bit. Both
product and reference pay one function-pointer call per slice. The stream uses the same
Xoshiro256++ implementation and seed 282 for every comparison.

The dependent scalar timer feeds `previous-previous` into an input-word XOR.
Every output is finite, so this is exact positive zero and preserves every
declared word. Strict FP compilation must retain that subtraction; inspect
its assembly and verify output identity before timing. Its common overhead
is included for both functions. The synthetic antithetic recurrence is
distinct from the engine's 54-contract pricing workload.

The shared protocol calibrates on this host, retains all pilots, targets
600 ms per sample and requires every timed duration to be at least 250 ms.
Every cell has ten independent processes and two paired rounds per process,
with alternating comparison order and warmups. After calibrating both
implementations, their common count is the larger calibrated count. This
preserves the exact same seeded word prefix in stream comparisons. Each process records affinity,
governor, frequency, load, CPU counters, SMT siblings and thermal readings
where available. Report those conditions with the result; no CI timing is
native performance evidence. Do not run unrelated builds/proofs while timing.

For each cell, take each process's mean paired log cost ratio. Its upper
one-sided 95% Student-t confidence ratio uses nine degrees of freedom and
the shared critical value 1.8331129326536335. Every required cell must have
that upper ratio at most one and valid durations. There is no aggregation
across cells, outlier removal or retry until passing. Failure or missing
evidence leaves the corresponding parity requirement unestablished.

This runner qualifies the declared workload on one native host. Linux and
macOS runs are separate decisions; their absolute timings are not compared.
Consumer pricing accuracy/cost remains separately qualified.

### Native Mac preparation and qualification

Use the same commands and input populations, omitting `--cpu`:

```sh
target/generators-venv/bin/python scripts/bench_fast/normal_pair/screen.py \
  prepare target/issue-282/macos-public-01
python3 scripts/bench_fast/normal_pair/screen.py \
  observe target/issue-282/macos-public-01
python3 scripts/bench_fast/normal_pair/qualify.py \
  target/issue-282/macos-public-01 --out target/issue-282/macos-qualification-01
```

Freeze a clean committed harness and identify the library release separately.
For a harness-only change, verify the library/architecture sources, workspace
manifests/lockfile and toolchain against that release before preparing; retain
both identities and the comparison command. Changed runtime sources need a new
explicit source decision, not the release's label. Each run uses a fresh output
directory; failed preparation and timing attempts are retained through review.

Before timing, finish compilation, oracle checks and disassembly inspection.
Use AC power and a quiet host; do not stop unrelated work without authorization.
Record `pmset` power/battery/thermal reports, `sysctl` hardware identity, process
CPU snapshots and load before and after each timing process. Telemetry commands
run outside measured intervals. Frequency and per-core residency are not sampled;
QoS does not prevent migration or interference. State these limits in the result.
The existing calibration, ten processes, two alternating paired rounds, minimum
duration and every-cell upper-95% rule apply without amendment. No automatic
retry or removal of slow samples is permitted.

The preparation contains the timer and wrapper binaries, exact input banks,
coefficient and source hashes, build logs, toolchain identities and frozen
runner/host/protocol copies. Native linkage records the Apple OS build, not
external implementation source. The final report must link the preparation and
all raw attempts, state unavailable telemetry, and separate observed errors from
the public whole-domain proof. A preparation or CI pass is not qualification.
